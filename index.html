Developer documentation

Humancha provides CAPTCHA challenges as WebP images. Your website can display the image directly or retrieve it with JavaScript for verification.

GET /api/captcha

Creates a challenge. The response body is the WebP image. The following response headers contain its session information: 

Content-Type: image/webp
X-Captcha-Session: session-id
X-Captcha-Hash: signed-challenge-token
X-Captcha-Expires: unix-timestamp

Display the image directly

<img
  src="https://YOUR-API-DOMAIN/api/captcha"
  alt="CAPTCHA"
>

This displays the image, but an img element cannot read the session and challenge headers. Use JavaScript fetch if your website needs to verify the answer.

POST /api/captcha/verify

Send a JSON request containing:

{
  "session_id": "session-id",
  "captcha_hash": "signed-challenge-token",
  "answer": "user-answer"
}

POST /api/captcha/refresh

Send the current session ID and challenge hash. The response is a new WebP image with new session headers.

What to expect

Challenges expire after their configured lifetime. Verification is performed server-side. Incorrect attempts are tracked against the CAPTCHA session. A replacement challenge receives a new session.
